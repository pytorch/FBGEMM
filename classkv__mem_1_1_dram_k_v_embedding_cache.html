◆ exclusive_hbm_register()

template<typename weight_type>
void exclusive_hbm_register ( at::Tensor cache_state,
at::Tensor cache_weights,
at::Tensor last_access,
bool set_associative = false )
inline

Exclusive HBM tier: the owner-local cache's copy is the only copy of a promoted row. The backend keeps the row's MetaHeader word (timestamp, count) as a tombstone in hbm_rows_ instead of a block, so lookups through the GPU cache, enrichment, eviction counts and checkpoints still see it. cache_state ([C, 1] int64 tags), cache_weights (uint8 rows in the DRAM storage format: [C, packed_bytes] g8 bytes for a packed_storage table, [C, dim + 8] INT8 codes then fp32 scale and bias for an int8_storage table, [C, dim * 2] fp16 columns for an fp16 table, which may instead use INT8 rows; columns past the enrichment dim, unused optimizer state in an embedding cache, are left out and read back as zero) and last_access ([C] int32 seconds) are the GPU cache's tensors (CPU tensors in tests).

Tombstones account for rows held in HBM or awaiting victim writeback. A GPU insert can evict a slot before its promotion runs; the promotion rechecks that slot under the shard lock used by victim writeback.

◆ refresh_hit_timestamps_under_wlock()

template<typename weight_type>
void refresh_hit_timestamps_under_wlock ( int shard_id,
const std::vector< int64_t > & ids )
inline

Sets the timestamps of ids that are still present and non-zero to now. Every training timestamp write happens under the shard write lock, so readers holding the read lock never see a concurrent write. Rows are re-found under the lock, so one evicted since the caller's lookup is skipped. now is read after taking the lock, so no earlier write carries a later timestamp. A row stamped ahead of now (clock stepped back, or a skewed checkpoint restored without restamping) is pulled back to now: the evictor's unsigned age check would otherwise evict it at once. Yields exactly like the enrichment write: the lock is held across rows and released only when a training lookup or write raises the interrupt flag, which is checked after every row.

Separate write path for enrichment that runs on enrichment_executor_ instead of the main executor_. This avoids competing with forward/backward for thread pool resources. Uses pause/resume to yield to fwd/bwd — removing this and reusing the main write path causes QPS regression. With skip_nonzero_rows, a key whose row is already non-zero keeps it. written_row_mask, when given, is set true at each position whose row was written and its stored row is non-zero (an all-zero row reads as absent).
